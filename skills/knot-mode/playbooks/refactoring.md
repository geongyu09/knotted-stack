# 리팩터링

동작은 바꾸지 않고 구성만 바꿉니다.

1. 리팩터링 전에 현재 동작을 고정합니다. 기존 테스트를 실행해서 통과를 기록하고, 테스트가 없으면 바꿀 부분의 입출력을 확인하는 테스트를 먼저 추가합니다.
2. 죽은 코드, 호출자가 하나뿐인 래퍼, 쓰지 않는 옵션을 먼저 삭제합니다. (`ponytail.md`)
3. 바꾸는 함수의 호출자를 전부 grep으로 찾습니다.
4. 한 번에 한 종류의 변경만 넣고, 변경마다 1번의 테스트를 다시 실행합니다.
5. 새 내부 API를 만들었다면 같은 작업 안에서 호출자를 전부 새 API로 바꾸고 옛 API를 삭제합니다.
6. 리팩터링 전후의 테스트 결과를 보고합니다.
