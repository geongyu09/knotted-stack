# delegate

에이전트 하나는 백그라운드에서 실행되는 `claude -p` 또는 `codex exec` 세션 하나이며, 이 스킬 폴더의 `scripts/agent.sh`로 만들고 관리합니다. 아래에서 `agent.sh`는 `<이 스킬의 폴더>/scripts/agent.sh`의 절대 경로로 바꿔서 실행합니다. Agent 도구의 서브에이전트는 사용하지 않습니다.

## 명령

| 명령 | 하는 일 |
| --- | --- |
| `agent.sh profiles` | 프로필 이름, 프로바이더와 모델, 사고 수준, 용도를 출력합니다. |
| `agent.sh create --title <제목> [--profile <이름>] [--provider claude\|codex] [--model <모델>] [--effort <수준>] [--cwd <폴더>] [--worktree <새 브랜치>] < 과제` | 에이전트를 만들고 id를 출력합니다. 과제에 `목표`와 `종료 조건`이 없으면 거부합니다. |
| `agent.sh wait <id>...` | 지정한 에이전트가 모두 끝날 때까지 기다린 뒤 상태를 출력합니다. |
| `agent.sh status [id]` | id, 상태(running, done, failed), 대화 횟수, 프로바이더와 모델, 제목을 출력합니다. |
| `agent.sh activity <id> [줄 수]` | 실행 중이거나 끝난 대화의 도구 호출과 발화를 최근 순서로 출력합니다. |
| `agent.sh read <id>` | 마지막 응답을 출력합니다. |
| `agent.sh send <id> < 후속 지시` | 같은 세션에 후속 지시를 보냅니다. 대화는 처음 과제를 포함해 3번까지만 허용됩니다. |
| `agent.sh archive <id>...` | 실행 중이면 멈추고 기록을 `archive/`로 보냅니다. |
| `agent.sh schedule add --cron "<cron 식>" <create 옵션> < 과제` | cron 시각마다 새 에이전트를 만들도록 사용자 crontab에 등록하고 스케줄 id를 출력합니다. |
| `agent.sh schedule ls`, `agent.sh schedule rm <스케줄 id>` | 등록한 스케줄을 보거나 지웁니다. |

상태 파일은 `~/.knotted-stack/agents/<id>/`에 있고, 에이전트는 `claude -p` 또는 `codex exec`로 권한 확인 없이 실행됩니다.

## 프로필 고르기

에이전트를 만들기 전에 `agent.sh profiles`를 실행해서 용도 설명을 읽고, 사용자가 이름을 말한 프로필이나 일에 가장 맞는 프로필을 `--profile`로 줍니다. 맞는 프로필이 없으면 `--provider`, `--model`, `--effort`를 직접 주고 사용자에게 프로필 없이 실행했다고 알립니다. 기본 프로필은 이 스킬 폴더의 `profiles.json`에 있으며, `~/.knotted-stack/profiles.json`을 만들면 그 파일이 기본 파일을 대신합니다.

## 스케줄과 반복 확인

- 정해진 시각마다 새 에이전트가 처리해야 하는 일은 `schedule add`로 등록합니다. 사용자의 crontab을 고치는 명령이므로 사용자가 요청했을 때만 실행하고, 등록한 뒤 스케줄 id와 cron 식을 보고합니다.
- 결과가 현재 대화로 돌아와야 하는 반복 확인(PR, 빌드, 배포 상태)은 스케줄이 아니라 Claude Code의 `/loop`를 씁니다.

## 과제 쓰는 법

과제는 혼자 읽어도 이해되도록 쓰며, 아래 항목을 채웁니다. 작업자 규칙(`worker.md`)은 스크립트가 과제 앞에 자동으로 붙입니다.

```
목표: 한 문장으로 적은 결과
종료 조건: 실행해서 참과 거짓을 가릴 수 있는 명령이나 확인 방법
범위: 고쳐도 되는 폴더와 파일
맥락: 작업자가 모르는 사실 (경로, 이미 확인한 내용, 금지 사항)
```

## 규칙

- 에이전트를 만든 뒤에는 `agent.sh wait <id>...`를 Bash의 `run_in_background: true`로 실행하고 턴을 끝내거나 다른 일을 합니다. 상태를 반복해서 조회하지 않으며, 오래 걸리는 에이전트가 멈췄는지 의심될 때만 `activity`로 확인합니다.
- 한 에이전트에게는 처음 맡긴 일과 같거나 비슷한 일만 `send`로 보냅니다. 다른 일은 새 에이전트를 만들어서 맡깁니다.
- 한 에이전트와의 대화는 3번을 넘기지 않습니다. 3번 안에 끝나지 않으면 `archive`하고 과제를 고쳐서 새 에이전트에게 맡깁니다.
- 작업자가 `BLOCKED`(종료 조건 5번 실패 포함)를 보고하면 같은 과제를 다시 보내지 않고, 부모가 목표나 종료 조건을 고치거나 없앱니다.
- 같은 파일을 고치는 에이전트를 동시에 실행하지 않습니다. 겹칠 수 있으면 `--worktree`로 작업 폴더를 나눕니다.
- 응답 전문을 대화에 붙여 넣지 않고, 결과 표와 문제별 짧은 요약으로 줄여서 적습니다.
- 결과를 반영한 뒤에는 `archive`합니다.

## 방식 1. 나누기 (swarm)

서로 독립인 조각을 여러 에이전트에게 나눠 맡깁니다.

1. 조각마다 목표, 종료 조건, 범위를 적습니다. 범위가 겹치면 나누기를 다시 합니다.
2. 에이전트를 한 번에 모두 만들고 `wait`를 백그라운드로 실행합니다.
3. 모든 조각의 결과를 읽습니다. 결과가 없는 조각은 통과로 세지 않고 빈칸으로 보고합니다.
4. 모든 조각의 결과를 표(조각, 결과, 증거)에 모아서 보고합니다.

## 방식 2. 겨루기 (arena)

같은 과제를 후보 2~3개가 각자 풀게 한 뒤 하나를 고릅니다.

1. 고르는 기준(통과 여부, diff 크기, 측정값)을 에이전트를 만들기 전에 적습니다.
2. 같은 과제로 에이전트를 만들되 `--worktree`로 브랜치를 나누고, 필요하면 `--profile`이나 `--model`을 다르게 줍니다.
3. 기준에 따라 기반이 될 후보 하나를 고르고, 탈락한 후보에서 더 나은 부분만 가져와 합칩니다.
4. 고른 후보, 기준별 비교 표, 가져온 부분을 보고합니다.

## 방식 3. 따지기 (interrogate)

변경이나 설계를 깨뜨려 보는 리뷰를 맡깁니다.

1. 리뷰 대상(diff, 브랜치, 설계 문서의 경로)과 지켜야 하는 성질을 적습니다.
2. 관점(정확성, 보안, 유지보수)마다 에이전트를 하나씩 만들고, 목표를 "성질을 깨는 입력이나 실행 순서를 찾기", 종료 조건을 "찾은 문제마다 재현 명령과 출력을 첨부"로 줍니다.
3. 재현 증거가 있는 지적만 채택하고, 증거가 없는 지적은 버립니다.
4. 채택한 지적을 심각도 순서로 보고합니다.
